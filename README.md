# Образовательная платформа: A/B-тест новой механики оплаты, SQL и автоматизация метрик

Учебный проект (Karpov Courses, 2023). Три части: анализ A/B-теста новой механики оплаты на онлайн-платформе, два SQL-запроса к ClickHouse и функции Python для пересчёта метрик по новым данным.

**Инструменты:** Python (pandas, scipy, seaborn, matplotlib), бутстрап, хи-квадрат, SQL (ClickHouse).

## Данные
Данные получены в рамках курса и в репозиторий не включены. Четыре файла: группы, дополнительные группы (пришли позже), активные пользователи в дни эксперимента и оплаты.

## Часть 1. A/B-тест
- Уникальных пользователей: 74 576, из них 8 341 заходили на платформу в дни эксперимента.
- Оплаты совершили 541 человек; 149 из них не заходили на платформу в дни эксперимента (18,4% суммы платежей). Причина неизвестна, поэтому в анализе они исключены, вместе с аномальной суммой 1900,0001.
- В анализе 392 активных платящих (78 в группе A, 314 в группе B).
- Группы разного размера (около 20% и 80%), что говорит о некорректном разбиении.

| Метрика | Группа A | Группа B | Результат |
| --- | --- | --- | --- |
| CR | 5,07% | 4,62% | различие не значимо (хи-квадрат) |
| ARPU | 47,35 | 58,06 | различие не значимо (бутстрап) |
| ARPPU | 933,59 | 1 257,88 | различие значимо (бутстрап) |

Выбор тестов: распределения не нормальные, поэтому t-тест не применялся; для CR использован хи-квадрат, для ARPU и ARPPU бутстрап.

**Вывод:** по ARPPU новая механика выигрывает, по CR и ARPU значимых различий нет, поэтому запуск возможен. Оговорки: около 30% платящих в тесте заплатили ровно 1 900 ₽, что может говорить о «фиксированном» платеже, а не об общем росте. В реальной работе я бы сначала исправил деление на группы и выяснил, откуда платежи от неактивных пользователей.

## Часть 3. Python
Две функции: пересчёт метрик (CR, ARPPU, ARPU) по основным и дополнительным данным и построение графиков по этим метрикам.
